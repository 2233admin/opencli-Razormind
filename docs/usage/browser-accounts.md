# 多账号登录

管理 → **账号登录**（`/browser-accounts`）管理不同网站及同一网站的多个账号，仅平台管理员可以操作。

1. 点击“添加账号”，选择常用网站或输入公开网站的网址/登录链接。快捷入口不是平台白名单。
2. 系统自动命名、创建独立持久化浏览器，直接显示真实登录画面。无需填写环境或远程桌面地址。
3. 在页面中扫码；也可点击画面中的输入框后键入/粘贴。中文、手机输入可用画面下方的输入工具。
4. 完成网站登录后点击“已完成登录，保存账号”。备注名可选；网站暴露可识别昵称时作为候选，否则沿用自动名称。

关闭窗口不清除登录会话。每个账号的 Cookie、Local Storage 留在独立浏览器 Profile；输入通过 Docker stdin 传输，不写入数据库、命令参数或环境变量。登录画面通过鉴权 API 按需刷新，响应禁止缓存，不保存截图。刷新二维码、切换登录方式通过真实网页完成。

登录画面复用按容器和 Profile 隔离的驱动连接，避免每次截图启动进程。闲置进程90秒后退出，最多保留16个驱动连接。画面轮询间隔600毫秒，点击期间暂停轮询并显示操作反馈；实际响应时间还包含网站加载。输入失败后停止后续输入，刷新按钮可恢复连接，不自动重发失败的密码或提交操作。

## 删除

账号卡片有直接删除入口。确认时必须明确选择：

- **同时清除登录数据**：删除账号记录、专属容器和匹配的持久化卷，无法撤销。只能清理系统创建且 Profile 校验匹配的环境。
- **保留登录数据**：实际删除账号记录，保留的环境继续隔离，不会发放给普通任务，也不能通过通用管理接口改换 Profile 或删除。当前界面没有重新关联这类保留环境的入口。

清理失败保留“等待删除完成”记录和隔离标记，可按原策略重试。删除策略在首次执行后固定，避免同时发出的保留/清除请求互相覆盖。旧版归档记录仍可恢复或删除。

## 状态和边界

“已确认登录”表示管理员最近24小时内确认完成，不能保证网站会话此刻仍有效；超过时间回到待确认，浏览器会话仍保留。网站是否要求重新验证由网站决定。系统不会把画面连接成功当作登录成功，也不自动规避验证码。

本功能支持本地 Docker 浏览器池；分布式 Redis/Celery 池的自动创建/清理暂不支持，会在副作用前明确拒绝。已绑定账号及保留环境不参与普通任务分配。工作流账号选择与授权路由不属于本页功能。

初始网址进行公开HTTP(S)地址校验；浏览器仍沿用既有平台管理员的网络权限。这不是强制逐跳出站隔离或面向不可信租户的浏览器服务。

## 运行和验证

启动迁移 `acc20260905a` 至 `acc20260905c` 后使用匹配的前后端版本。复用 `CHROME_IMAGE`、`COMPOSE_PROJECT_NAME`、`NOVNC_BASE_PORT` 配置及 Docker 网络。镜像需要 Chromium CDP（容器内9222）及支持 fetch/WebSocket 的 Node。前端经后端代理显示画面，无需访问 noVNC 端口。

`ENV_FILE_PATH` 指定动态端点持久化文件；创建/删除和重启读取同一配置。预览前端3113连接后端8032，使用独立 `artifacts/account-preview/admin.db`，不替换8031部署。

验证包含账户API/权限/保留数据/清理失败重试、输入校验、取消后驱动退出、池隔离、浏览器管理防护，以及 Playwright 网址创建→内嵌操作→确认→两种删除策略→手机布局流程。真实扫码由账号持有人完成。

## 验收纠正记录（2026-09-05）

旧版将账号名称、登录环境和桌面地址交给用户填写，限定三个网站，并用归档替代删除。用户指出这不符合登录任务。根因是把底层资源管理当作终端用户流程。本版改为“网站→系统准备→页面内登录→保存”，不额外创建全局规则。
