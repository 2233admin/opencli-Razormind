# 从目标创建项目并继续处理结果

这条路径适用于当前源码中的项目创建、全局 Agent 会话和任务与通知。改动来源及适配边界见 [OpenAlice 复用记录](../research/openalice-ui-adoption.md)。

## 创建工作

在「项目」选择工作区，再打开「创建」菜单：

- **创建空白工作流**：填写名称，点击「创建并打开」。项目、主工作流和第一份草稿一起保存；失败时保留名称，可重试。
- **描述需求创建**：写明数据从哪里来、怎样处理、保存或发送到哪里，以及是否需要重复执行。生成后会保存项目草稿；页面显示保存修订。补充需求会更新同一草稿，手工编辑与生成修改冲突时先处理差异。
- **从模板创建 / 导入 DSL**：以模板或已有定义为起点，再检查实际来源、连接和输出配置。

在窄屏的需求创建页，先显示输入需求的区域。「工作流方案」与「Agent 对话」切换时保留输入和画布。首次保存后，工作区锁定为草稿所属工作区；要创建另一个项目，先返回项目列表。

生成失败时可以使用本地规则形成初稿。初稿的节点结构不代表已经接通真实网站、模型或交付连接。页面会提示缺失配置；保存草稿与发布运行是不同步骤。

## 让全局 Agent 创建或修改草稿

1. 点击顶部 **Agent**，核对工作区。可描述「创建公开新闻采集项目，保存数据，每天检查一次」，或要求查看当前项目的工作流草稿。
2. Agent 读取项目、工作流和草稿时直接返回结果；创建项目或修改草稿时先显示 **待确认操作**。检查名称、图修改及范围，再点击 **确认执行**。
3. 确认成功后，点击 **打开 Agent 保存的工作流草稿**。链接使用后端真正保存的项目和工作流 ID。后续在原会话继续说明修改需求，会保留已创建项目的上下文。
4. 暂时不想执行时选择 **暂不执行**。它只收起当前提示，不代表撤销后台提案。刷新后，未处理的提案仍可以恢复。

顶部 Agent 需要可用的模型连接及工作区权限。模型返回了提案不等于写入已经完成；只有确认成功才会修改项目。草稿在另一处被修改后，旧修订的提案会失败，需要重新读取草稿并生成提案。

## 从通知与结果继续原来的工作

「任务与通知」待处理列表同时展示普通审批和 Agent 变更提案。两者有独立的操作方式：普通审批填写审批理由；Agent 提案点击 **继续原会话**，在原会话检查并确认。

确认后的 Agent 提案出现在 **项目动态**。条目根据真实来源提供项目、运行记录、具体运行以及原会话的入口。没有保存会话来源的旧条目不会虚构一个原会话。

项目的数据、证据和运行页面保留工作区、项目、工作流及运行上下文。从具体运行选择 **讨论本次结果** 会打开带该运行上下文的 Agent；只有明确保存了原会话 ID 的来源才显示 **继续原会话**。

会话选择器支持搜索当前已加载的会话。通知中的确切会话链接可以恢复未出现在最近会话列表中的旧会话。没有访问权限、会话不存在或链接范围不匹配时，界面提示原因，不自动打开其他会话。

## 验证与发布

打开正式编辑器后，保存草稿、验证当前修订，再发布版本并运行。修改草稿不会改变已有发布版本。具体运行、数据保存和交付验证参见 [完整使用说明](product-manual.md#验证发布运行)。

本轮连接的是持久项目草稿、会话与来源导航。真实采集、定时执行和外部投递仍由各自的节点、版本、调度及连接负责；本轮自动化验收使用隔离数据库和浏览器接口夹具，不会向真实接收方发送内容。
